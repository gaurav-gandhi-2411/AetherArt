# Pre-Registration: Ukiyo-e LoRA A/B (Powered Primary Run)

**Committed BEFORE the run executes.** This fixes the endpoint, threshold, and decision rule in
advance so the promotion call cannot be adjusted after seeing results. Do not edit this file to
match a result once generation/scoring has started — if the design needs to change, that change
belongs in a new commit with its own rationale, not a silent edit here.

## Background

`docs/MODEL_VERDICT.md` §4 originally ran the published-vs-curated Ukiyo-e LoRA A/B on the
general 30-prompt PartiPrompts benchmark and found a wash on all axes. That benchmark contains no
ukiyo-e trigger prompts, so `artifact_absence` (the metric the curated retrain specifically
targeted) hit a floor effect in both arms (worst case 0.7 in both) — the wash is not informative
about whether the retrain fixed the calligraphy/cartouche defect, only that neither checkpoint
regressed off-domain. A preliminary n=12 targeted check on the 4 existing ukiyo-e-style prompts
(`scripts/eval_prompts.yaml`'s `lora_001`-`004`) was suggestive (paired diff/SEM = 2.03) but
underpowered and thin on figure/portrait coverage (only one figure subject, which didn't
discriminate — both checkpoints scored it a perfect 1.0). This document pre-registers a properly
powered follow-up.

## Statistical method

**Paired difference** (curated minus published, matched by identical `prompt_id`+`seed` across
both arms — both checkpoints generate the same 30×3 grid in the same order, so record *i* in one
arm is the same prompt+seed as record *i* in the other). SEM computed directly on the 90
per-pair differences, not the independent-sample quadrature combination
`sqrt(SEM_published² + SEM_curated²)`.

**Why paired, stated independently of any result:** both arms share an identical prompt set,
identical seed set, and an identical base checkpoint (only the LoRA weights differ) — this is a
matched-pairs design by construction. Paired analysis removes prompt-difficulty variance that is
common to both arms (an inherently "hard" prompt scores relatively lower on both checkpoints; an
easy one scores relatively higher on both), which the independent-sample formula cannot exploit
and which inflates its SEM estimate for exactly this data shape. This is the standard, more
statistically powerful choice for matched designs regardless of which way any individual result
comes out — it was applied identically to the earlier (n=90 general-benchmark and n=12
preliminary-targeted) results in `docs/MODEL_VERDICT.md` §4.1/§4.2 before this run was designed,
not chosen after seeing this run's numbers.

## Endpoints (fixed before running)

- **Primary endpoint:** `artifact_absence`, paired diff (curated − published), on the 30-prompt
  set above.
- **Promotion threshold:** paired diff / paired SEM > 2.0 — this project's established
  significance bar (`scripts/check_eval_gate.py`'s CI regression gate, PR #20; also the bar
  applied throughout `docs/MODEL_VERDICT.md` §4).
- **Guardrails (non-inferiority):** `style_adherence`, `figure_preservation`. Guardrails pass if
  their paired diff does **not** show curated scoring worse than published by more than 2×SEM in
  the negative direction. Guardrails are not endpoints to optimize — they only need to not
  regress.
- **LPIPS-vs-`sdxl_base`:** not scored on this set (no `sdxl_base` reference images exist for the
  `lora_*` prompt set — `sdxl_base` was only run on `pp_*`). Not needed for this design: LPIPS
  was a style-lift sanity check on the general-benchmark guardrail (§4.1), not part of this
  primary/guardrail pair.

## Decision rule (fixed before seeing results)

**Promote the curated retrain over the published checkpoint if and only if:**
1. The primary endpoint clears the promotion threshold (diff/SEM > 2.0), **and**
2. Neither guardrail shows a regression clearing 2×SEM in the negative direction.

**If the primary does not clear the threshold, or a guardrail regresses:** do not promote. Report
the actual result (null, negative, or a guardrail failure) as the finding. This is not grounds to
lower the threshold, drop a guardrail, subset the prompts, or re-run with a different seed set
looking for a passing result — any of those would be exactly the kind of after-the-fact tuning
this pre-registration exists to prevent.

## What happens after this file is committed

The 30-prompt set generates + scores for both checkpoints (`reports/lora_ab_30prompt_{published,curated}.json`
or equivalent), the paired analysis runs, and `docs/MODEL_VERDICT.md` §4.3/§4.4/§5/§6 are updated
with the actual numbers and the resulting promote/no-promote call — governed by the rule above,
not re-litigated at that point.
