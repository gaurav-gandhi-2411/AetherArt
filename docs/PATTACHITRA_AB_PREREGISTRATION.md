# Pre-Registration: Pattachitra LoRA (Curated Adapter vs. `sdxl_base`)

**Amended 2026-07-24 before any training run executes.** This fixes the endpoint, threshold,
decision rule, and power characterization in advance so the evaluation call cannot be adjusted
after seeing results. Do not edit this file to match a result once training/generation/scoring
has started — a change to the design itself belongs in a new commit with its own rationale.

**Amendment rationale (why this supersedes the original three-arm design below the fold):** the
ukiyo-e session established, with real n=90 paired data, that the **arm-to-arm (curated vs.
uncurated) effect sits roughly 20× below the independent-axis VLM rubric's own minimum detectable
effect (~0.037, `docs/MODEL_VERDICT.md` §4.7)**, and that a binary OCR proportion test is a further
~6× worse (§4.9). Pre-registering that same arm-to-arm comparison as a gating endpoint for
Pattachitra would commit to an endpoint the instrument cannot resolve at this n — exactly the
mistake rule "never pre-register an endpoint below the instrument's MDE" exists to prevent. The
comparisons that *did* resolve cleanly for ukiyo-e were each LoRA arm vs. `sdxl_base`
(style_adherence 1.68–2.82×SEM, artifact_absence 3.11–3.49×SEM, §4.8) — those are what this
amendment pre-registers as primary instead.

## Background — carrying forward this session's lessons, not repeating them

The Ukiyo-e LoRA A/B (`docs/MODEL_VERDICT.md` §4) went through: a correlated single-call VLM
judge producing an inflated headline (§4.3), a withdrawal after independent-axis rescoring (§4.6),
a root-cause audit (§4.7–§4.8), and a higher-power-metric attempt that was *lower*-power than the
rubric (§4.9). This pre-registration bakes those lessons in from the start:

1. **Independent-axis VLM scoring is the only scoring regime used** — one Ollama call per axis,
   no single-call variant to accidentally reach for.
2. **The base-model (no-adapter) comparison IS the primary design**, not a post-hoc diagnostic —
   this amendment's central change.
3. **Power is reported alongside every result, regardless of outcome.** "Did not clear the bar"
   and "no effect" are different claims, both pre-committed to being distinguished.
4. **The OCR binary detector is run as a secondary, non-gating signal only** — §4.9 found it
   ~6× less powered than the rubric for this style domain.
5. **NEW — do not pre-register an endpoint the instrument cannot resolve.** The curated-vs-
   uncurated comparison is dropped as a gating endpoint (see below), not carried forward
   unexamined.

## Why curated-vs-uncurated is DROPPED as a gating endpoint (not just deprioritized)

This is a deliberate, power-aware design choice, stated explicitly rather than left implicit:

- **The effect this comparison would measure is small.** Ukiyo-e's arm-to-arm `artifact_absence`
  diff was +0.0078 (0.583×SEM at n=90) — curation recovered only ~16% of the LoRA-induced
  regression vs. base (§4.8). Resolving an effect that size at adequate power requires ≈1,963
  paired samples (§4.7) — impractical at zero-cost-local scale, and disproportionate to spend GCP
  budget chasing for a *second* LoRA project when the first one already established the
  approximate magnitude.
- **Curation is adopted as default practice anyway, on the directional evidence already in
  hand** — not because its marginal effect was statistically proven, but because: (a) it
  directionally helped in the one case it was measured (~16% regression recovery, §4.8), (b) the
  curated arm's style-adherence lift over base was *also* directionally better than the uncurated
  arm's would be expected to be (curated 2.82×SEM vs. published/uncurated-equivalent 1.68×SEM in
  the ukiyo-e case), (c) no measured downside was ever found from curating — no guardrail
  regressed from curating in the ukiyo-e A/B, and (d) **the intervention is free**: one automated
  VLM-judge filter pass over an already-assembled corpus, zero marginal GCP cost, zero additional
  training runs. When an intervention has directional-positive-or-neutral evidence, zero
  measured downside, and zero marginal cost, requiring formal proof of its marginal effect before
  adopting it is not a rigor-preserving stance — it is spending real budget to re-derive a
  conclusion the null result already supports at the only scale this project can afford to test it.
- **This is not "we didn't test it."** It was tested, on the highest-quality real data available
  (ukiyo-e's own n=90 paired result). The finding — small effect, correct direction, no
  downside — is exactly what justifies adopting curation as standard practice while declining to
  re-litigate its magnitude on a second, smaller corpus that cannot resolve it either.
- **Practical consequence:** only the curated Pattachitra corpus is trained. No uncurated control
  run. This halves GCP spend and removes an endpoint this design cannot answer, rather than
  pre-registering it and producing a second underpowered null needing the same disclosure ukiyo-e
  needed.

## Design

- **Arms:** two, generated and scored together:
  1. `sdxl_base` — no LoRA adapter at all (the reference point).
  2. Pattachitra LoRA trained on the **curated** corpus only (111 images,
     `reports/pattachitra_precheck_report.json` / `docs/NEXT_MODEL_SPEC.md` §3.5). No uncurated
     arm is trained (see rationale above).
- **Trigger token:** `pattascroll` (novel, no embedding collision — same role `ukyowood` played
  for ukiyo-e). Every prompt includes it.
- **Prompt set:** unchanged from the original design — 30 prompts (`pat_001`–`pat_030`) spanning
  Pattachitra's actual subject range (mythological/religious scenes, courtly and village genre
  scenes, animals, floral/nature motifs), with deliberate figure/portrait coverage. See the full
  list preserved in git history (this file's prior revision) or `scripts/eval_prompts.yaml` once
  added there for the actual run.
- **Seeds:** 42, 43, 44.
- **n:** 30 prompts × 3 seeds = 90 paired records per arm (180 total generations across 2 arms —
  down from 270 in the original 3-arm design).
- **Generation:** SDXL base (+ LoRA where applicable), `negative_prompt` = "text, watermark,
  caption, museum label, calligraphy, signature, words, letters" (targets Pattachitra's actual
  dominant contamination classes — museum-photography artifacts, not in-print calligraphy, per
  `docs/NEXT_MODEL_SPEC.md` §3.5), 30 inference steps, guidance_scale 7.5, 1024×1024. Identical
  generation config for both arms — only the LoRA weights (or their absence) differ.
- **Training config:** rank-8 LoRA, SDXL base + `madebyollin/sdxl-vae-fp16-fix`, 1024×1024,
  1500 steps, batch size 1 × gradient accumulation 4, learning rate 1e-4, fp16, seed 42,
  `--validation_epochs 15` (per `docs/NEXT_MODEL_SPEC.md` §4's already-fixed validation-overrun
  issue) — the same recipe as ukiyo-e's curated retrain, for direct effect-size comparability
  across the two LoRA projects. Checkpoint-select at steps 500/1000/1500, as with ukiyo-e.
  **111 training images is ~5× ukiyo-e's curated set (23)** — the "below the floor for a coherent
  rank-8 LoRA" concern raised for ukiyo-e's smaller set does not apply here on corpus size grounds
  (though it remains an empirical question the eval below actually answers).
- **Scoring:** independent single-axis VLM judge (`scripts/model_verdict_harness.py`'s
  `score_vlm_judge`, one Ollama call per axis, `qwen2.5vl:7b`) on `style_adherence`,
  `figure_preservation`, `artifact_absence`, in a second phase after the generation pipeline is
  released from GPU memory. **Plus** the OCR binary detector (`scripts/detect_text_artifacts.py`,
  `n_detections >= 1` rule) as a secondary signal over the same images.
- **Requires `ollama serve` running locally** with `qwen2.5vl:7b` pulled. Zero paid APIs.

## Statistical method

**Paired difference** (curated LoRA − `sdxl_base`, matched by identical `prompt_id`+`seed`), same
paired-diff/SEM methodology as ukiyo-e's §4.8 base-model comparison — SEM computed on the 90
per-pair differences directly, not independent-sample quadrature combination.

## Endpoints (fixed before running)

- **Primary endpoint A — `style_adherence`, paired diff (curated − `sdxl_base`).** Threshold:
  diff/SEM > 2.0 to count as a demonstrated style-adherence lift over the base model's own prior.
  This is the "does the adapter add real value" question, and the one ukiyo-e's equivalent
  comparison answered most cleanly for the curated arm (2.82×SEM).
- **Primary endpoint B — `artifact_absence`, paired diff (curated − `sdxl_base`).** Reported with
  its own diff/SEM regardless of direction or significance — **this is a measured
  cost/characterization, not a pass/fail gate.** Ukiyo-e's precedent (§4.8) found both LoRA
  variants there significantly *regressed* `artifact_absence` vs. base (3.11–3.49×SEM); if the
  same holds here, it is disclosed on the model card exactly as done for ukiyo-e
  (`docs/HF_MODEL_CARD_UPDATES.md`), not treated as disqualifying — the ukiyo-e adapters remain
  published with this same tradeoff disclosed.
- **Guardrail (non-inferiority) — `figure_preservation`, paired diff (curated − `sdxl_base`).**
  Pass if the diff does not show a regression clearing 2×SEM in the negative direction.
- **Required power reporting (mandatory, regardless of outcome):** for every endpoint above, the
  paired SEM's implied MDE at 80%/90% power (§4.7's method) and the 95% CI on the observed diff,
  reported in the same section as the point estimate. A result must be labeled "clears the bar,"
  "does not clear the bar and rules out an effect of size X," or "underpowered below the MDE to
  distinguish a smaller true effect from none" — never a bare pass/fail without this context.
- **Secondary, non-gating signal:** OCR binary detector's result on curated vs. base (McNemar
  exact test where paired, or the raw flagged-proportion otherwise), reported for directional
  consistency only. §4.9's validation numbers (94% precision / 77% recall, MDE ~0.22) do not
  transfer to Pattachitra's different contamination profile (museum labels/captions, more
  Latin/mixed script than ukiyo-e's stylized pseudo-kanji per `docs/NEXT_MODEL_SPEC.md` §3.5) — if
  the OCR signal is to be trusted beyond a directional check here, it needs its own
  `scripts/validate_text_detector.py`-style validation pass on Pattachitra images specifically.
  Absent that, it is reported as an unvalidated-for-this-domain secondary signal only.

## Decision rule (fixed before seeing results)

**Report the adapter's characterization, do not retrain to a better-looking result:**
1. If primary endpoint A (`style_adherence`) clears +2×SEM over base: the adapter demonstrates a
   real style lift. If it does not: **that is a finding, reported as such** — "the adapter did
   not demonstrate a style-adherence lift over `sdxl_base` at this n," together with its MDE and
   CI. This is not grounds to retrain with different hyperparameters, a different step count, or a
   different seed looking for a passing result.
2. Primary endpoint B (`artifact_absence`) is reported with its number regardless of direction —
   a disclosed cost (or, if it does not regress, a disclosed non-finding), matching the model-card
   tradeoff-disclosure convention already established.
3. The guardrail (`figure_preservation`) must not regress >2×SEM; if it does, that is reported and
   weighed alongside endpoint A's result in the overall characterization — not silently dropped.
4. **No promotion/publication decision is triggered by this evaluation alone** — HF publication
   remains blocked on the read-only token regardless of outcome (task-level constraint, unrelated
   to these results).
